# UI Review

- 审查目标：src/prototypes/vehicle-management（车辆资产 · 入口 `index.tsx`）
- 使用设计依据：src/resources/design-system/DESIGN.md（OneOS V2）
- 生成时间：2026-07-27 01:10

## 总体点评

车辆资产整体已落在 Stripe Fintech / OneOS V2 语汇上：画布与卡片层级清楚，列表台账密度高但不失可读，车牌/VIN 使用 `tabular-nums`，状态 Pill 语义色（已交车绿、运营态绿点）与主色链接触达一致。详情「车辆档案工作台」信息分区完整——基本信息、交车合规摘要、生命周期、证照、运维指派——生命周期头栏「事件名称 + 搜索/筛选」对齐感良好，是值得保留的高保真亮点。

主要风险不在视觉「像不像 V2」，而在三条强制规则的落差：① H5（≤767px）多处核心筛选触控高仍停留在 PC 紧凑尺寸（约 28–30px）；② 操作列虽接入了 `OperationActions` 组件，却把「查看详情」全部收入「更多」，与 §3.16 定稿布局冲突；③ 台账筛选仍大面积使用 `LnSelect`，未消费 DESIGN 强制的 `V2Select`（含 H5 Bottom Sheet）。Detector 未报 AI-slop 类静态命中，说明问题集中在规范合规与触控，而非装饰性堆砌。

## P0-P3 优先级问题

### P0 - H5 主筛选触控热区未达 44px

- 证据：390×844 视口实测——业务线 Pill（「全部 642」等）约高 28px；台账 Pill（「全部车辆 (1021)」等）约高 30px；「车牌多选 / 搜索车牌」触发器约高 28px。`DESIGN.md` §4.2 / §3.0.2 要求 ≤767px 可点击控件 `min-height ≥ 44px`。导出/更多筛选/卡片「更多操作」已达 44px，说明并非整页未适配，而是筛选带遗漏。
- 影响：App 嵌入 / 手机浏览器下，分类切换与车牌检索是最高频路径，误触与点不准会直接阻断扫车找车。
- 修复方向：在 `@media (max-width: 767px)` 或 `data-viewport="h5"` 下，将 `.va-pill`、KPI 分类 tab、`V2FilterSearch` / 车牌多选触发器统一拉到 ≥44px，正文字号 ≥14px；可参考租赁合同 H5 筛选条高度策略。

### P0 - 操作列将「查看详情」收入「更多」，违反 OperationActions 定稿

- 证据：`ListView.tsx` PC 台账与 H5 卡片均仅传 `more={[查看详情, 设置运维负责人, 编辑档案]}`，未传 `view` / `edit`；预览中行操作仅见 `⋯`。「更多操作」热区本身 44×44 合规，但布局不合规。对照 `DESIGN.md` §3.16 与 `src/common/operation-actions-spec.md`：详情须外侧固定第一；禁止「详情入口被收入更多」。
- 影响：最高频「进档案」被多点一次隐藏，且与故障处置、租赁合同等已对齐母版的操作列习惯不一致，增加扫视与学习成本。
- 修复方向：恢复 `view={{ label: '查看详情', onClick }}` 外侧第一；工作流按规范最多外显 1 个（如「编辑档案」或「设置运维负责人」二选一），其余进 `more`。勿再仅传 `more` 伪装成「更干净」。

### P1 - 筛选控件使用 LnSelect，未落实 V2Select

- 证据：`ListView.tsx` 引入并多处渲染 `LnSelect`（车牌多选旁、更多筛选内多字段）；390 视口 DOM 存在 `.ln-select-trigger`，未见 `.v2-select-trigger`。母版租赁合同筛选已用 `V2Select`。`DESIGN.md` / 全局规则要求业务原型统一 `UIComponents` 封装控件，H5 下拉应走 Bottom Sheet。
- 影响：深浅色、Focus、触控高与 Bottom Sheet 行为与设计系统脱节；后续主题色/若依动态主色联动成本升高。
- 修复方向：筛选与详情生命周期阶段选择逐步替换为 `V2Select`（及日期类 `V2SingleInputDateRangePicker` 等），删除对原生/`LnSelect` 的依赖样式兜底。

### P2 - 双层分类 Pill 语义接近，窄屏认知负担偏高

- 证据：列表同时存在「全部 / 租赁 / 物流」（KPI/在租口径）与「全部车辆 / 租赁 / 物流 / 库存 / …」（台账运营态）两套横向 Pill；H5 下第二套需横向滚动，选项可见数 >4。
- 影响：不阻断任务，但「租赁」一词在两层含义不同（在租业务线 vs 运营态），窄屏下易误选或重复滚动。
- 修复方向：区分文案（如上层「在租·租赁」/下层「运营态·租赁」），或 H5 将一层收入「更多筛选」/分段说明，降低同词冲突。

### P3 - 生命周期搜索 Focus 环被局部关掉

- 证据：`style.css` 中 `.va-life__search input:focus-visible { outline: none; }`（另有个别 `outline: none`）；页级虽有统一 `focus-visible` 描边，搜索框局部覆盖削弱可见焦点。
- 影响：键盘用户在长生命周期列表内定位时反馈减弱；对比度与主任务影响有限。
- 修复方向：去掉该覆盖，或改为 `--ln-primary-focus` / `--ln-focus-ring` 的 2px 环，与全页一致。

## 核心元件

### Bento / 在租车型占比

- 保留：4 卡进度条 + 租赁/物流/库存分段色清晰；「查看全部车型」H5 已 44px。
- 调整：与下方台账 Pill 的口径关系建议在标题或 tooltip 再点明「在租口径」，避免与运营态混淆（见 P2）。

### 列表筛选条（Pill + 搜索 + 更多筛选）

- 保留：Pill Tabs 视觉贴近 V2；工具栏导出/导入/列设置权重正确；列个性化入口存在，符合复杂台账强制项方向。
- 调整：H5 高度（P0）、`LnSelect`→`V2Select`（P1）；确认「查询后收起更多筛选」规则在交互上仍成立。

### 台账表 / H5 卡片

- 保留：车牌链接触达 + 状态 Tag、定位套件、保险双行、运维空态「无运维负责人 · 去设置」可读；H5 已卡片化；数字等宽。
- 调整：操作列按 §3.16 恢复外侧「查看详情」（P0）。

### 详情工作台 / 生命周期

- 保留：页头「返回 + 车辆档案工作台」简洁；车牌后车辆状态 Tag；生命周期「事件名称」筛选与概览卡、关键次数快捷跳转完整；证照区空值「未上传」语义清楚。
- 调整：阶段/事件筛选控件与列表统一到 `V2Select`；补全搜索 Focus（P3）。

### OperationActions

- 组件已正确引入样式与封装，但**用法**偏离定稿（仅 `more`）。按规范回调即可，无需自建菜单皮肤。

## 响应式与可访问性

- 桌面（≥1024）：台账多列 + sticky 品牌/操作列观感正常；主色与 hairline 消费 Token，未见外壳深内容浅失配。
- H5（390）：已切卡片列表，主操作/更多按钮多数达 44px；**缺口集中在 Pill 与车牌搜索触发器**（P0）。分页上一页/下一页约 36px，接近但未满 44，可随筛选带一并抬高。
- 键盘/焦点：页级 `focus-visible` 存在；生命周期搜索存在局部关闭（P3）。
- 对比度：正文/次要文/主色链接在浅色模式下目视可达 AA 意图；未做自动化 contrast 扫描。
- `prefers-reduced-motion`：生命周期相关过渡有降级规则，符合规范方向。
