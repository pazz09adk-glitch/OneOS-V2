| 项 | 内容 |
|---|---|
| 模块名称 | 验车入库 |
| 所属系统 | ONE-OS（PC）+ 外勤 Web/小程序/APP |
| 交互原型 | `/prototypes/vehicle-inspection` |
| 业务条线 | 运维管理条线 · 入库入口 |
| 文档状态 | AutoPRD · 首版 |

---

## 1. 一句话与目标

**一句话**  
采购合同审批通过后自动生成验车任务；运维在现场登记 VIN、记录通过/不通过与证据，通过后经 E签宝签署验收报告并入库。

**本期目标**  
1. PC 验车任务列表与详情  
2. 部分通过可结案；拒收留痕并可发起重新交付  
3. 外勤三端对齐《附件4：车辆交接验收表》：基本信息、分组检验项（√/N/×/O）、双签、45°照片、车辆识别代码 OCR  
4. 入库回写车辆资产（原型 localStorage 桥）  
5. 大数量合同按到车追加明细  

**非目标**  
- 真实 OCR / 真实 E签宝 API  
- 纸质表扫描自动结构化入库（仅人工/外勤填报）  

---

## 2. 用户故事

| 角色 | 起点 → 运作 → 闭环 |
|------|-------------------|
| 运维（PC） | 打开验车任务 → 查看应验台数与现场结果 → 通过车辆入库 / 结案 |
| 运维（外勤） | 打开绑定任务 → OCR/手输 VIN → 通过并 E签 或不通过+证据 → 回写 PC |
| 采购 | 从采购合同跳转查看关联验车进度 |

---

## 3. 关键逻辑

详见 `.spec/vin-and-closure.md`。

## 4. 验收重点

1. 合同通过后任务自动出现  
2. VIN 非法不可通过  
3. 不通过必须原因+证据；通过须检查项+现场照片+E签模拟文件  
4. 部分通过可结案；入库车辆可在车辆资产列表看到（同源浏览器）  

## 5. 假设

- 外勤三端暂放仓库根目录，由产品自行移动后再挂导航  
- 与 PC 共用 localStorage，需同域访问
