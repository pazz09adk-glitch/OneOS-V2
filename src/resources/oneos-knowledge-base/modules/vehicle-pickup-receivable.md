# 提车应收款

| 项 | 内容 |
|---|---|
| 模块 ID | `vehicle-pickup-receivable` |
| 条线 | lease |
| 责任部门 | 财务 / 业务管理组 |
| 置信度 | 架构推导 · 待校验（`architecture`） |

## 页面说明

- **应收台账**：提车前应收与实收匹配分配
- **对齐办理**：关联收款记录并触发交车

## 角色与权限

| 角色 | 权限要点 |
|------|----------|
| 财务 | — |
| 业务员 | — |

## 起点 → 运作 → 闭环

- **起点**：合同生效产生提车应收
- **怎么运作**：见下方操作说明与正向步骤。
- **闭环**：提车款对齐且交车任务已生成

## 前置条件

- 租赁合同已生效且存在提车应收

## 操作说明（主路径）

1. 导入/同步收款流水
2. 应收与实收匹配分配
3. 对齐完成触发运维交车任务

## 业务规则

- 对齐是交车门禁
- 与收款记录双向关联
- **业财基准**：见 [biz-finance-integration](../foundations/biz-finance-integration.md)
  - ≤15 日提车：剩余天租金+保证金+剩余天服务费；＞15 日：当月+下月整月租金+保证金+整月服务费
  - 先开票须审批后财务开票上传；后开票关联收款后通知财务开票
  - 实收=应收可交车；不足须特批

## 正向 / 逆向

**正向**（摘要同上操作说明）

**逆向 / 边界**

| 情况 | 系统表现 |
|------|----------|
| 金额未对齐 | 不可触发交车 |
| 重复分配超额 | 拦截 |
| 实收不足无特批 | 不可交车 |

## 禁止与边界

- 未收款对齐强制交车
- 无关联假性付清

## 关联与触发

- → **oneos-web-ops**：对齐后生成交车任务
- → **payment-records**：关联收款
- → **biz-finance-integration**：全链条业财门禁
